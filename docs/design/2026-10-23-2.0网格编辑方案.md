# 2.0 网格编辑 · 方案

状态：2026-10-23 草案，等用户确认后实现。替换《2.0 小组件系统》里“档位 + 前移后移”的编辑方式。

## 1. 要解决什么

2026-10-23 用户看过 2.0 和 10 种排版原型后的反馈：

1. 卡片只能调宽度（S/M/L/XL），高度跟内容走，调不了。
2. 去掉点按钮交换位置，重点做拖动调整位置。
3. 库体检拆开，每一项单独一张卡，能各自调大小。
4. 页面没铺满屏幕，两边留白。

已和用户确认的选择：

| 问题 | 选择 |
|---|---|
| 高度怎么调 | 编辑时拖卡片右下角，宽和高一起调，按格子吸附 |
| 宽屏怎么铺满 | 保持 12 列，按窗口宽度等比拉宽 |
| 手机 | 跟随电脑布局排成一列，只看不改 |

关于第 4 条的事实：留白和 2K 屏无关，是样式里写死了 `.vp-shell { max-width: 1360px }`（`styles.css` 第 131 行），任何宽于约 1400px 的窗口都会两边留白。

## 2. 参考的做法

这是“仪表盘网格编辑器”的经典问题，成熟方案是 gridstack.js、react-grid-layout、Grafana 面板：

- 每张卡存 `x, y, w, h`（列、行、占几列、占几行），网格吸附。
- 拖动时原位置留一个虚线占位框，被挡住的卡片实时让开。
- 卡片自动往上浮（“重力”），版面不会留洞。
- 右下角拖柄调大小，每张卡有最小、最大尺寸。

本方案照这个模型做，不引入第三方库：上面几个库要么依赖 React，要么体积大，而且拖动要和 Obsidian 的滚动容器、主题配合，自己写可控。核心算法（碰撞、上浮、推开）是纯函数，便于单元测试。

## 3. 数据结构

```ts
interface GridItem {
  id: WidgetId;
  x: number; // 第几列开始，0–11
  y: number; // 第几行开始，0 起
  w: number; // 占几列，1–12
  h: number; // 占几行
}
interface WidgetLayout {
  version: 2;
  items: GridItem[];
}
```

- **行高**：一行 40px，行间距 16px，h 行高度 = 40h + 16(h−1)。现在的数字卡 152px 正好是 3 行。
- **宽度**：12 列按窗口宽度等比分，窗口越宽卡片越宽，高度不变。
- **卡片目录**里，原来的 `sizes: ["s","m","l","xl"]` 改成每张卡的尺寸范围：`minW maxW minH maxH` 和默认 `w h`（见第 6 节）。
- 布局仍存在 `settings.layout`，随 data.json 同步。设置版本升到 6。

### 迁移

- **v1（2.0 开发中的 S/M/L/XL 布局，只在你本机）**：按原来的顺序从左到右、从上到下摆进网格，宽度用原来的档位列数，高度用这张卡的默认高度。原来的“库体检”一张，换成 6 张拆分后的卡，放在它原来的位置。
- **没有布局（从 1.8 升级）**：直接用默认布局。
- **读到坏数据**（同步冲突、手改）：去掉未知卡和重复卡，尺寸夹到范围内，重叠的往下推开，然后整体上浮。

## 4. 拖动换位置

只在电脑上、编辑模式里可用。删除现在的前移、后移按钮和 HTML5 拖放，改用 Pointer 事件自己实现：HTML5 拖放拿不到中途位置，做不了实时让位，拖动的样子也由浏览器决定，没法控制。

### 过程

1. **按下**：在卡片任意空白处按下（工具按钮除外）。移动超过 4px 才算开始拖，避免误触。
2. **拖动中**：
   - 卡片跟着指针走，1:1 不加缓动，略微抬起（阴影加深、放大 1.02 倍）。
   - 原来的格子位置显示虚线占位框，吸附到最近的网格位置。
   - 被占位框挡住的卡片往下让开，其余卡片往上补位，都有 200ms 的平滑移动。
   - 指针靠近滚动区上下边缘 48px 时自动滚动。
3. **松开**：卡片 160ms 落进占位框，保存一次。拖动过程中不保存，也不重画卡片内容，只改位置。
4. **取消**：按 Esc，所有卡片回到拖动前的位置。

### 键盘（无障碍，没有可见按钮）

- 聚焦卡片后，方向键移动一格，Shift + 方向键调大小。
- Delete 键移除这张卡。
- 每次操作用读屏播报，例如“写作节奏，第 2 列第 5 行，4 × 4”。

## 5. 拖右下角调大小

- 编辑模式里，每张卡右下角出现一个拖柄。
- 拖动时卡片轮廓实时变化，角上显示“6 × 4”这样的列 × 行。被挤到的卡片同样让开。
- 尺寸夹在这张卡的最小和最大范围里，拖不出范围。
- **卡片内容跟着变**：每跨过一个格子，就按新尺寸重画这张卡的内容（每帧最多一次），你在拖的时候就能看到“多显示几行”“图表变高”。
- 撤销：编辑期间记录最近 20 次改动，按 Cmd/Ctrl + Z 撤销。编辑栏里也有“撤销”按钮。

### 编辑模式的界面

- 页面顶部一条编辑栏：撤销、恢复默认布局、添加卡片、完成。
- 卡片右上角一个 ×（移除），右下角一个拖柄；悬停时卡片描边。卡片上方原来的工具条（尺寸档位、前移、后移）全部去掉。
- **添加卡片**：点一下，卡片加在最下方第一个放得下的位置，页面滚过去，新卡闪一下。

## 6. 卡片内容按实际尺寸变化

原则：**内容看卡片的实际像素宽高**，不看占几列。同样是 4 列，在 2K 屏上更宽，就多显示一些；在窄窗口里更窄，就少显示一些。用 ResizeObserver 量卡片正文区。

每张卡都有一个高度范围，在这个范围里内容能跟着有意义地变化；超出范围只会多出空白，所以拖不出去。下表的数字是起始值，实现时要在 1280 和 2560 两种宽度下逐卡实测再定。

| 卡片 | 宽（列） | 高（行） | 默认 | 变高 / 变宽时多出什么 |
|---|---|---|---|---|
| 今日写作 | 4–12 | 4–8 | 8×6 | 宽 ≥ 约 700px：圆环 + 连续打卡 + 本周七天；再高：今日新建、今日改动、今天写过 |
| 接下来 | 3–12 | 3–12 | 4×6 | 按高度显示行数；宽了显示所属笔记 |
| 笔记、总字数、任务完成率、本月写作 | 2–6 | 2–4 | 3×3 | 2 行只有数字；3 行加迷你图；4 行迷你图变高 |
| 写作热力图 | 6–12 | 4–6 | 12×5 | 宽了显示更多周；高了格子变大 |
| 每周写作 | 4–12 | 4–10 | 8×7 | 图表高度等于正文高度；宽了柱子更多 |
| 常用标签 | 3–12 | 3–12 | 4×7 | 按高度显示行数 |
| 写作节奏 | 3–8 | 3–6 | 4×4 | 柱子变高；高 ≥ 4 加数值标注 |
| 笔记活跃度 | 3–8 | 2–4 | 4×4 | 高 3 以上加说明 |
| 最常被链接 | 3–12 | 3–12 | 4×4 | 按高度显示行数 |
| 文件夹构成 | 3–12 | 2–6 | 4×3 | 矮时图例横排；高时图例变成带篇数的列表 |
| 任务最多的笔记 | 3–12 | 3–12 | 4×3 | 按高度显示行数 |
| 链接密度 | 2–6 | 2–4 | 4×3 | 一个数字，高了加孤立笔记占比 |
| 写作回顾 | 6–12 | 3–6 | 12×4 | 宽 ≥ 8 列周报和月报并排，窄时上下叠 |
| ★ 断链 | 3–12 | 3–12 | 4×5 | 按高度显示行数，修复 / 创建按钮照旧 |
| ★ 孤立笔记 | 3–12 | 3–12 | 4×5 | 同上 |
| ★ 同名笔记 | 3–12 | 3–12 | 4×5 | 同上 |
| ★ 空笔记与超大笔记 | 3–12 | 3–12 | 4×4 | 同上 |
| ★ 未引用的附件 | 3–12 | 3–12 | 4×4 | 同上 |
| ★ 重复内容 | 3–12 | 3–8 | 4×4 | 没扫描过时显示“开始扫描” |

### 列表放不下时

- 卡片显示放得下的行数，最后一行改成“还有 N 个 ›”。
- 点了以后卡片里面变成可滚动的列表，**卡片高度不变**，再点“收起”回去。这样展开永远不会把页面拉长，也就不会再出现 1.6 修过的“收不回”问题。
- 现在库体检里各栏互相影响的手风琴（同一时间只能展开一栏）随拆分一起去掉。

## 7. 库体检拆成 6 张卡

- 每张卡标题旁显示数量，有问题时用警示色（沿用现在的 warn 样式）。
- 各自保留现在的操作：断链的“修复（可撤销）/ 创建笔记”，孤立笔记“打开”，附件“删除”，同名“查看”，重复内容“开始扫描”。
- 原来卡片头上的“实时 · 21:30 更新”和“共 49 项可整理”：更新时间看板顶部已经有了，去掉；“共 N 项可整理”放进页首的总结句（“… · 库里有 49 项可整理”）。
- 计算逻辑（`checkupModel`）不动，只是改由 6 个渲染函数分别取用。

## 8. 铺满屏幕

- 去掉 `.vp-shell` 的 `max-width: 1360px`，左右保留 24px 边距。
- 12 列等比拉宽，行高固定。2K 屏上每张卡更宽，图表（热力图、每周写作）用上多出来的宽度，列表每行更长。
- 已知代价：在超宽屏上，一张很宽的列表卡，文字和右侧数字之间会离得很远。可以在实现时给列表行加一个最大宽度，或者由你把这类卡拉窄。

## 9. 窄窗口和手机

- 看板容器宽度 ≥ 760px：按网格显示，可以编辑。
- **< 760px（手机、平板竖屏、Obsidian 里分屏的窄面板）**：
  - 排成一列，顺序按网格里从上到下、从左到右读。
  - 宽度 ≤ 3 列的小卡两张一行。
  - 高度用内容的自然高度，不用电脑上存的行数（电脑上的行数是按宽卡算的，在窄屏上不对）。
  - 隐藏编辑按钮；电脑上面板太窄时点编辑会提示“把面板放宽到 760px 以上再编辑”。
- 手机上的显示跟着电脑布局自动变，不单独存一份。

## 10. 默认布局

12 列，单位是格子。默认把库体检拆出来的 6 张卡放在最下面两行。

```
y0   今日写作 8×6                     | 接下来 4×6
y6   笔记 3×3 | 总字数 3×3 | 任务完成率 3×3 | 本月写作 3×3
y9   写作热力图 12×5
y14  每周写作 8×7                     | 常用标签 4×7
y21  写作节奏 4×4 | 笔记活跃度 4×4 | 最常被链接 4×4
y25  文件夹构成 4×3 | 任务最多的笔记 4×3 | 链接密度 4×3
y28  断链 4×5 | 孤立笔记 4×5 | 同名笔记 4×5
y33  空笔记与超大笔记 4×4 | 未引用的附件 4×4 | 重复内容 4×4
y37  写作回顾 12×4
```

链接密度从 3 列改成 4 列，现在那一行末尾空一列的洞就没有了。

## 11. 动效

- 拖动：被拖的卡跟手，其余卡 200ms 让位，松手 160ms 落位。
- 调大小：轮廓实时变化，内容按格子重画；松手后其余卡片平滑归位。
- 加卡：淡入并闪一下；移除：淡出，下面的卡往上补位。
- 打开“减少动态效果”或在设置里关掉动效时，以上全部直接到位，没有过渡。

## 12. 不做什么

- **不做像素级自由摆放，也不允许重叠**。卡片吸附格子并自动上浮。
- **不做每台设备一份布局**。用户已选择手机跟随电脑。
- **手机上不能编辑**。
- **不做布局模板**。10 种排版原型可以以后做成“一键套用的模板”，这次不做。

## 13. 实现分步

每一步单独提交，2.0 全部完成后统一发布。

1. **网格引擎**（纯函数 + 单元测试）：碰撞、上浮、拖动推开、调大小夹范围、找第一个空位、v1 → v2 迁移、坏数据修复。
2. **按坐标渲染 + 铺满**：CSS grid 用 `grid-row` 和 `grid-column` 精确定位，去掉最大宽度。
3. **内容随尺寸变化**：逐卡定尺寸范围，列表按高度算行数，图表填满高度；加“还有 N 个”的内部滚动。
4. **库体检拆成 6 张卡**，迁移旧布局。
5. **拖动**：占位框、实时让位、自动滚动、Esc 取消；删掉前移、后移按钮和 HTML5 拖放；键盘移动和调大小。
6. **拖右下角调大小**，加撤销。
7. **窄屏一列**、编辑栏、文档（README、CHANGELOG、设计文档）。

## 14. 验收标准

- **自动检查**：
  - 网格引擎单元测试：任意拖动、调大小之后，不重叠、不越界、没有洞（上浮后）。
  - 每张卡在最小、默认、最大三种尺寸下，1280 和 2560 两种宽度、中英文，都不超出，没有文字被挤成一个字一行，空白不超过一行。
  - 用 Playwright 发 Pointer 事件做拖动和调大小的端到端测试（Pointer 事件可以测，HTML5 拖放不行），覆盖 Esc 取消、自动滚动、撤销。
  - 760px 以下排成一列，顺序正确，没有编辑入口。
  - 测试、build、lint、样式检查全部通过。
- **你在 Obsidian 里实机验收**：
  - 拖动的手感。
  - 在 2K 屏上铺满。
  - 手机跟随布局显示。

## 15. 风险

- **工作量**：这一版等于重写编辑系统，比 2.0 前五步加起来还大。2.0 的发布会相应推后。
- **高度和内容的配合**：每张卡都要为一段高度范围设计内容。范围定得不好，要么拖高了只多出空白，要么拖矮了被截断。第 3 步逐卡实测就是为了这个。
- **Obsidian 里的滚动容器**：自动滚动和指针捕获要在真实 Obsidian 里验证，预览环境只能部分模拟。
