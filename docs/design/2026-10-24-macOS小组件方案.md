# macOS 桌面小组件方案

日期：2026-10-24　状态：插件这一侧已实现，Swift 宿主 app 和小组件尚未开始

## 目标

在 Mac 桌面上放一个 Note Pulse 小组件，不打开 Obsidian 也能看到：今天写了多少字、打卡没有、本周七天、逾期和今天到期的任务、今天的日程，以及一句问候。

## 结论

可以做。原生桌面小组件只有一种做法：用 WidgetKit 写一个 Swift 的 app extension，随一个 macOS app 一起安装。Obsidian 插件是 JavaScript，装不进小组件，所以整条链路分成两半：

1. 插件这一半（已完成）：把看板已经算好的数字整理成一份快照 JSON，写到固定位置。
2. 原生这一半（未做）：一个很小的宿主 app 读这份 JSON，放进 App Group 共享容器，WidgetKit 小组件从共享容器读取并显示。

```
Obsidian 插件                      宿主 app（Swift，常驻菜单栏或登录项）         小组件（WidgetKit extension）
  统计刷新 / 日程变化                 监视 widget-snapshot.json                     TimelineProvider 读 App Group
        │                                   │                                           ▲
        ▼                                   ▼                                           │
 <库>/.obsidian/plugins/note-pulse/  ──►  复制到 App Group 容器  ──► WidgetCenter.reloadAllTimelines()
        widget-snapshot.json
```

## 为什么要这么绕

- **小组件读不到库里的文件。** 小组件跑在沙盒里，只能访问自己的容器和 App Group 共享容器，不能读用户任意文件夹。Obsidian 库通常在 iCloud Drive 或 `~/Documents` 下，小组件直接读不到。
- **所以需要一个宿主 app 做搬运。** 宿主 app 可以不开沙盒（自己用，不上架），能直接读库里的快照文件；也可以开沙盒，让用户在 app 里选一次库文件夹，用 security-scoped bookmark 记住授权。搬运的方式是把 JSON 复制进 App Group 容器。
- **小组件刷新靠宿主 app 通知。** 小组件自己没有常驻进程，系统按时间线（timeline）和预算安排刷新。宿主 app 复制完文件后调用 `WidgetCenter.shared.reloadAllTimelines()`，小组件才会马上更新。
- **为什么不让插件直接写进 App Group 容器。** 容器路径在 `~/Library/Group Containers/` 下，Obsidian 插件在桌面端有 Node，技术上写得进去。路径由 group id 决定，而 group id 在 macOS 上通常带开发者团队标识，换签名就可能变；把它写死在插件里会很脆弱，由宿主 app 去复制，路径只有宿主 app 知道（团队标识的规则未核对，开工时查 Apple 文档）。

## 为什么需要完整的 Xcode

- WidgetKit 小组件是 app extension，要用 Xcode 的工程结构（App target + Widget Extension target）、签名、App Group 能力（entitlements）和打包流程来生成。
- 本机目前只装了 Command Line Tools，没有 Xcode。命令行工具带有 Swift 编译器，可以编译单个 Swift 文件和 Swift Package，但 app extension 需要的工程模板、签名配置和 `xcodebuild` 的 app 打包流程在 Command Line Tools 里没有。
- 小组件预览（Xcode 里的 Widget Preview / Canvas）也只在完整 Xcode 里有。

> 未经验证：不装 Xcode，用手写的 Info.plist 加 `swiftc` 加 `codesign` 拼出 extension 理论上走得通，但没有人维护这条路线，出问题没处查，不建议。

## 快照文件

- 位置：`<库>/.obsidian/plugins/note-pulse/widget-snapshot.json`（与 `data.json` 同目录，设置页会显示完整路径）。
- 开关：设置 → 刷新与行为 → 导出小组件数据，默认关闭。关闭时文件被删除。
- 写入时机：每次统计刷新完成后、日程或设置变化后；写盘防抖 2 秒；写之前和磁盘上的内容比对（忽略 `generatedAt`），没变就不写。看板没打开时，开关打开的情况下每 5 分钟检查一次：库有变化就在后台重新统计，没有变化就只按当前时间重新生成（问候语和提示随时段变化，跨天后“今天”也要翻页）。
- 所以 `generatedAt` 的含义是“内容最近一次变化的时间”。小组件想显示“多久前更新”可以用它；想判断插件是否还活着，看文件的修改时间不可靠（内容不变时不写），需要时再加一个心跳字段。

### 字段表（version 1）

约定：日期是本地日期字符串 `YYYY-MM-DD`，不带时区；字数是整数，单位“字”（汉字按字、英文按词）；目标为 0 表示没设；`generatedAt` 是 ISO 8601 UTC。version 不变，字段名、类型、单位就不改；要改先升 version，Swift 端遇到不认识的 version 应当显示“请更新”。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number | 固定 1 |
| `generatedAt` | string | 内容最近一次变化的时间，ISO 8601 UTC，例如 `2026-10-24T13:00:00.000Z` |
| `language` | `"zh"` / `"en"` | `greeting`、`hint` 用的语言，跟随插件的界面语言 |
| `date` | string | 快照所说的“今天” |
| `greeting` | string | 问候语加今天的状态，一整句，例如“晚上好，今天的目标达成了，写了 520 字” |
| `hint` | string / null | 最需要留意的一件事（逾期、今天到期、连续打卡快断了、周目标快到期等）；没有就是 null |
| `today.words` | number | 今天写了多少字 |
| `today.goal` | number | 每日目标（字），0 = 没设 |
| `today.checkedIn` | bool | 今天是否已打卡：达到每日目标，或写了日记；没设目标时写了任何字就算 |
| `today.streak` | number | 当前连续打卡天数；今天还没打卡时从昨天往回数 |
| `week.start` | string | 本周一的日期 |
| `week.words` | number | 本周已写字数（周一到今天） |
| `week.goal` | number | 每周目标（字），0 = 没设 |
| `week.days` | array | 固定 7 项，下标 0 是周一，6 是周日 |
| `week.days[].date` | string | 这一天的日期 |
| `week.days[].weekday` | number | ISO 星期，1 = 周一 … 7 = 周日 |
| `week.days[].words` | number | 当天写了多少字；今天之后为 0 |
| `week.days[].checkedIn` | bool | 当天是否算打卡；今天之后为 false |
| `week.days[].isToday` | bool | 是不是今天 |
| `tasks.overdue` | number | 已逾期的任务数 |
| `tasks.dueToday` | number | 今天到期的任务数 |
| `tasks.top` | array | 最急的至多 3 条：先逾期（最早到期的在前），再今天到期 |
| `tasks.top[].text` | string | 任务文字，已去掉日期、优先级标记，超过 80 个字符以 `…` 收尾 |
| `tasks.top[].due` | string | 到期日 |
| `tasks.top[].overdue` | bool | 是否已逾期 |
| `agenda.date` | string | 日程所属日期，等于 `date` |
| `agenda.items` | array | 今天的日程，按添加顺序，至多 20 条 |
| `agenda.items[].text` | string | 日程文字 |
| `agenda.items[].done` | bool | 是否已勾选 |

代码：`src/widget-snapshot.ts`（纯函数 `buildWidgetSnapshot`）；测试：`tests/widget-snapshot.test.ts`。

## 隐私与同步

- 快照里有任务文字和日程文字，默认关闭，设置页的说明里写明了这一点。
- 它和 `data.json` 在同一个目录，随库一起被 iCloud、Obsidian Sync 等同步。两台电脑都打开导出时，各自按自己的统计写同一个文件，后写的覆盖先写的，内容基本一致（统计口径相同、字数按设备合并），差别只在刚写完那几分钟。只在做小组件的那台 Mac 上打开这个开关就不存在这个问题。
- 手机上没有桌面小组件的需求，建议关闭。

## 后续要做的事

1. 装完整 Xcode，建一个 macOS app 工程，加 Widget Extension target，开 App Group 能力（两个 target 用同一个 group id）。
2. 宿主 app：选库文件夹（或直接读默认路径）、监视快照文件（`DispatchSource` 或 FSEvents）、变化时复制进 App Group 容器并调用 `WidgetCenter.shared.reloadAllTimelines()`；做成菜单栏 app 或登录项，开机自启。
3. Swift 端用 `Codable` 解析快照；`version` 不认识时显示提示；`generatedAt` 太旧（比如超过一天）时显示“数据已过期”。
4. 小组件设计：小号（今天字数加进度环加连续天数）、中号（再加本周七天）、大号（再加任务和日程）；亮暗色跟随系统；配色用看板的设计令牌（见 `2026-10-22-质感规范.md`）。
5. 点击小组件打开 Obsidian：`obsidian://` URL scheme（比如打开插件的看板命令，或者带 vault 参数的链接）；需要先确认能不能直接拉起看板，可能要新增一条命令加 `obsidian://adv-uri` 之类的方式，未验证。
6. 签名与分发：自己用的话，个人开发者账号加本地签名即可；要给别人用需要付费开发者账号做公证。App Group 在 macOS 上的 group id 格式有平台差异，开工时对照 Apple 当前文档确认，这里不下结论。
7. 如果宿主 app 要读被沙盒保护的目录（iCloud Drive 里的库），先决定开不开沙盒，再决定授权方式。

## 本次实现范围
